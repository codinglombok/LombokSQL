# LombokSQL

[![License](https://img.shields.io/badge/license-Apache--2.0%20OR%20MIT-blue)](LICENSE-APACHE)

A universal SQL compiler: one **JSON AST** becomes deterministic, **parameterized SQL** for PostgreSQL, MySQL, SQLite and SQL Server. No runtime dependencies, no database connection, no I/O. The output is byte-identical across language ports.

Part of the [Lombok Ecosystem](https://github.com/codinglombok).

## Why this library?

Many programs have to build SQL dynamically: web services, CLI and ETL tools, serverless functions, edge gateways, test-data generators and migration tools. Existing query builders are usually tied to one language, one driver or one ORM, so the same logic is rewritten in every language and behaves slightly differently each time.

LombokSQL separates two concerns:

1. **The contract**: a normative JSON AST specification (`docs/SPEC_LombokSQL_v0.1.0.md`) and shared test vectors.
2. **The implementation**: a small compiler per language. Because the AST is plain data, it can be stored, sent over the network, cached, inspected or generated by any language, and compiled wherever the target dialect is known.

Usage scenarios:

- **Web services and APIs**: turn dynamic request filters into a safe `WHERE` clause without string concatenation.
- **ETL and CLI tools**: run one query definition against a local SQLite database in tests and PostgreSQL in production.
- **Serverless and edge**: a `no_std + alloc` Rust core and a dependency-free TypeScript package suit environments with strict size limits.
- **Embedded devices and gateways**: build SQL statements for a remote database from firmware without a large library.
- **Data generators and migration tools**: consistent `INSERT`, upsert and bulk update statements across dialects.

Other dependents in the Lombok Ecosystem are listed in `docs/map_LombokSQL_v0.1.0.md`.

## Features

Every feature below is covered by vectors in `vectors/` and by TypeScript tests.

- `SELECT`: columns, aliases, `DISTINCT`, subqueries in `FROM` and in the column list, `JOIN` (inner, left, right, full, cross), `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`, `LIMIT`/`OFFSET`.
- Conditions: `and`, `or`, `not`, comparisons, `like`, `ilike`, `in` (list or subquery), `between`, `is null`, `exists`, and raw parameterized conditions. Parentheses are emitted only when required.
- `INSERT` (multiple rows), upsert (`ON CONFLICT` and `ON DUPLICATE KEY`), `RETURNING`.
- `UPDATE` and `DELETE`. **A missing `WHERE` is rejected** (`missing_where`) unless `all: true` is stated explicitly.
- Every value is always a bound parameter. Every identifier is always quoted for the dialect. Value text never appears in the SQL.
- Dialect-specific placeholders: `$1`, `?`, `@p1`.
- Dialect-specific pagination (SQL Server uses `OFFSET ... FETCH`).
- Errors carry a canonical `code` and a `messageId` for translation; nesting is limited to 64 levels.

## Installation

Not published to any registry yet. After the first release:

```bash
npm install lomboksql      # TypeScript / JavaScript
cargo add lomboksql        # Rust
```

## Quick Start

### TypeScript

```ts
import { select, eq, gt, and, compile } from "lomboksql";

const q = select("u.id", "u.name")
  .from("users u")
  .where(and(eq("u.active", true), gt("u.age", 18)))
  .orderBy("u.id", "desc")
  .limit(10);

q.build("postgres");
// { sql: 'SELECT "u"."id", "u"."name" FROM "users" AS "u" WHERE "u"."active" = $1 AND "u"."age" > $2 ORDER BY "u"."id" DESC LIMIT 10',
//   params: [true, 18] }

q.build("mssql").sql;
// SELECT [u].[id], [u].[name] FROM [users] AS [u] WHERE [u].[active] = @p1 AND [u].[age] > @p2 ORDER BY [u].[id] DESC OFFSET 0 ROWS FETCH NEXT 10 ROWS ONLY

// Or directly from an AST (the cross-language contract):
compile({ type: "select", from: "t", where: { op: "eq", left: "id", right: { value: 1 } } }, "sqlite");
```

### Rust

```rust
use lomboksql::compile_json;

let r = compile_json(
    r#"{"type":"select","from":"t","where":{"op":"eq","left":"id","right":{"value":1}}}"#,
    "postgres",
).unwrap();
assert_eq!(r.sql, r#"SELECT * FROM "t" WHERE "id" = $1"#);
assert_eq!(r.params_json(), "[1]");
```

## Port status

| Port | Status | Evidence |
|---|---|---|
| Rust (`no_std + alloc`) | YES, passes the vectors | `rust/tests/vectors.rs` runs every vector |
| TypeScript | YES, passes the vectors | `typescript/test/vectors.test.ts` runs every vector, plus builder and fuzz tests |
| Python, Go, PHP, Java, Kotlin, C#, C/C++, Swift, Perl | NOT YET | No code; planned once the contract is stable (see `docs/development_ide_LombokSQL_v0.1.0.md`) |

Vectors: 716 cases (556 golden cases with hand-written expectations, 160 generated regression cases) across four dialects. Integration: 36 scenarios executed on SQLite, PostgreSQL and MySQL (`integration/run.mjs`).

## Standards implemented

The output contract is defined by `SPEC_`. Target dialects and minimum feature versions (PostgreSQL, MySQL, SQLite, SQL Server) are listed there. See "Known limitations".

## Known limitations

- **Execution on real databases is tested for SQLite 3.51, PostgreSQL 16 and MySQL 8.0** (36 scenarios per engine, all of which must return the same results; see `integration/`). **SQL Server does not pass completely yet**: in the first CI run, 29 of 36 scenarios passed and 7 failed because of the `text` column type in the fixture (not because of the generated SQL); the fixture has been fixed and a re-run is pending. The minimum versions stated in `SPEC_` have not been tested one by one, only the versions above.
- Not yet available: `UNION`/`INTERSECT`, CTEs (`WITH`), window functions, DDL (`CREATE TABLE`, migrations), `NULLS FIRST/LAST`, `RETURNING` for MySQL and SQL Server, upsert for SQL Server (`MERGE`).
- SQL functions and `raw` are not validated; `raw` is trusted SQL written by the developer, never user input.
- Every `?` inside `raw` is a placeholder; a literal question mark must be passed as a parameter.
- Only Rust and TypeScript have code. The fluent builder exists only in TypeScript.
- No third-party security audit yet. Fuzzing is pseudo-fuzzing, not `cargo-fuzz`.
